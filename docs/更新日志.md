# 群约小助手版本演进日志

## 维护约定

- 仓库目前没有正式的 GitHub Release / Tag，下面按提交演进补齐内部版本号。
- 版本号统一使用 `1.x.y` 三级：`1` 作为当前产品代际主版本，`x` 表示产品阶段跃迁，`y` 表示该阶段内的连续增强、修复与整理。
- 历史版本内容只允许通过 `git show`、`git diff`、`git log` 等只读方式查看，不直接切换旧版本覆盖当前工作区，避免旧内容影响现在内容。
- 以后每次 GitHub 有新提交、合并或发布，只要功能、交互、架构、安全、部署、测试、文档基线发生变化，都要在同一次改动里同步更新本文件。

### 后续新增版本时怎么写

建议每次按下面顺序更新本文件：

1. 先执行 `git fetch --all --tags` 与 `git log --reverse --oneline`，确认最新提交位置。
2. 用 `git show <commit>` 和 `git diff <prev> <commit>` 只读查看新增内容，不切换旧版本覆盖当前文件。
3. 判断是否属于“大跨越”：
   - 如果是架构重构、产品阶段跃迁、工程体系升级，升阶段版本，如 `1.4.3 -> 1.5.0`。
   - 如果是连续增强、修复、整理，升补丁版本，如 `1.4.2 -> 1.4.3`。
4. 给版本起一个能概括核心变化的名字。
5. 在“版本总览”和“各版本升级点”两处同时补齐。
